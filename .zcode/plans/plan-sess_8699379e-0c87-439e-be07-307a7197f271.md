# 需求模块接口调整方案

## 改动总览（7 项需求）

### 1. 需求列表改分页 + 多条件搜索
- 新建通用 `PageVO<T>`（recall-common，含 list/total/page/pageSize）
- 新建 `RequirementPageReq`（page/pageSize/keyword/startDate/endDate/status）
- 接口地址 `GET /api/requirements/page`（分页专用路径）
- Service `list` 改为 `page(RequirementPageReq)`，用 MyBatis-Plus `Page` + `LambdaQueryWrapper`：
  - keyword：title LIKE（忽略 null/空）
  - startDate/endDate：createdAt 范围
  - status：精确匹配
  - 按 id DESC 排序

### 2. 简化绑定的 K 信息
- 删除 RequirementVO 中的 `KeyResultVO keyResult` 字段，改为内嵌简单对象 `RequirementKeyResultVO`（仅 id/name/status）
- 删除对 `KeyResultService.getVOById` 的调用（不再查 sprintIds/records 等重数据）
- 详情/编辑/绑定返回时，用 `keyResultService.getById(krId, false)` 取 entity，仅映射 id/name/status
- 同步删除 `KeyResultService.getVOById` 接口方法及实现（本次新增的，可安全删）

### 3. 创建/编辑需求支持传入 keyResultId
- `RequirementCreateReq` 加 `Long keyResultId`（可空）
- `RequirementUpdateReq` 加 `Long keyResultId`（可空）
- create：传了 keyResultId 则走绑定逻辑（复用 bindKr 校验+同步逻辑），未传则不绑
- update：传了 keyResultId 则绑定（若与当前绑定不同先解绑再绑），null 表示解绑（回讨论中）

### 4 & 5. 删除独立绑定/解绑接口
- 删 `RequirementController.bindKeyResult` / `unbindKeyResult`
- 删 Service 的 `bindKeyResult` / `unbindKeyResult` 公共方法（绑定逻辑下沉为 private 复用方法供 create/update 调用）
- 删 `RequirementBindKrReq` DTO

### 6. 文档类型改三态
- `RequirementDocumentType` 枚举改为：PROTOTYPE("prototype" 原型设计)/REQUIREMENT("requirement" 需求文档)/MEETING("meeting" 会议纪要)
- schema.sql 注释更新；实库无枚举约束无需 ALTER

### 7. 文档删除更新接口
- 删 `RequirementDocumentController.update` 及 `RequirementDocumentService.update`
- 删 `RequirementDocumentUpdateReq` DTO
- 文档只保留 create + delete
