# 日报接口文档（v1.0）

> 本文档供前端对接「日报」功能使用。所有接口需 JWT 登录，userId 由后端从令牌解析，前端无需传。

## 一、功能概述

日报用于记录每天的工作内容，支持按月表格渲染、每天多条工作内容、每条工作内容可关联 0~N 个待办。

**核心规则**：

| 规则 | 说明 |
|---|---|
| 一天一份 | 同用户同日期只有一份日报（唯一约束） |
| 禁止未来日期 | 保存日报时日期不可晚于今天，否则 4601 |
| 全量覆盖 | 保存日报时整体提交当天全部工作内容，后端先删后插 |
| 关联待办范围 | 只能关联「当天相关」的待办（生命周期覆盖该日期），否则 4602 |
| 物理删除 | 删除日报连带删工作内容项与关联，不可恢复 |
| 月度查询 | 只返回有日报的天，没填的天不返回，前端自行补空格 |

### 「当天相关」待办定义

待办的生命周期区间覆盖某日，即视为该日相关：

```
createdAt ≤ date  且  (doneAt 为空  或  doneAt ≥ date)
```

即当天创建的、当天完成的、历史创建当天仍 pending 的，均当天可见。

## 二、错误码

| 错误码 | 含义 | 触发场景 |
|---|---|---|
| 4601 | 不能填写未来日期的日报 | 保存日报时 date > 今天 |
| 4602 | 待办在该日期不可关联 | 关联的待办生命周期不覆盖该日期 |
| 404 | 资源不存在 | 查询/删除不存在的日报，或关联不属于自己的待办 |
| 422 | 参数校验失败 | 工作内容为空、进度越界等 |

## 三、接口列表

基础路径：`/api/daily-reports`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/daily-reports?month=2026-07` | 月度日报列表 |
| GET | `/api/daily-reports/{date}` | 单日日报详情 |
| PUT | `/api/daily-reports/{date}` | 保存日报（全量覆盖） |
| DELETE | `/api/daily-reports/{date}` | 删除日报 |

> `{date}` 格式 `YYYY-MM-DD`，如 `2026-07-09`。
>
> 查询某天可关联的待办，请用待办接口 `GET /api/todos/by-date/{date}`（返回当天真实状态快照），见待办模块文档。

## 四、接口详情

### 4.1 月度日报列表

`GET /api/daily-reports?month=2026-07`

**请求参数**

| 参数 | 位置 | 必填 | 校验 |
|---|---|---|---|
| month | query | 是 | `YYYY-MM` |

**响应**：`Result<DailyReportMonthVO>`

```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "month": "2026-07",
    "reports": [
      {
        "id": 1,
        "reportDate": "2026-07-08",
        "items": [
          {
            "id": 1,
            "content": "完成首页改版",
            "progress": 100,
            "todos": [
              { "id": 10, "title": "首页改版", "status": "1", "doneAt": "2026-07-08T10:00:00" }
            ]
          }
        ],
        "createdAt": "2026-07-08T18:00:00",
        "updatedAt": "2026-07-08T18:30:00"
      }
    ]
  }
}
```

> `reports` 只含填了日报的天，按日期升序。没填的天不返回，前端按月表格自行补空格。

---

### 4.2 单日日报详情

`GET /api/daily-reports/{date}`

**响应**：`Result<DailyReportVO>`，结构同 4.1 中 `reports` 的单个元素。不存在返回 404。

---

### 4.3 保存日报（全量覆盖）

`PUT /api/daily-reports/{date}`

**请求体**：`DailyReportSaveReq`

```json
{
  "items": [
    {
      "content": "完成首页改版",
      "progress": 100,
      "todoIds": [10, 11]
    },
    {
      "content": "接口联调",
      "progress": 50,
      "todoIds": []
    }
  ]
}
```

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| items | DailyReportItemReq[] | 是 | 不能为空（@NotEmpty） |
| items[].content | string | 是 | 不为空，最长 2000 字符 |
| items[].progress | int | 是 | 0-100 |
| items[].todoIds | long[] | 否 | 不传或空表示不关联待办；重复 id 自动去重 |

**语义**：

- 不存在该日期的日报 -> 新建；存在 -> 覆盖其下全部工作内容项与关联。
- **全量覆盖**：提交的 items 即为当天最终内容，旧内容（含关联）全部删除后重新插入。
- items 不能为空（不允许提交空日报）。若要清空某天日报，请用 DELETE。

**校验失败**：

| 场景 | 错误码 |
|---|---|
| date > 今天 | 4601 |
| 关联待办不存在/不属于自己 | 404 |
| 关联待办当天不可见（不相关） | 4602 |

**响应**：`Result<DailyReportVO>`，保存后的完整日报（含生成的项 id）。

---

### 4.4 删除日报

`DELETE /api/daily-reports/{date}`

物理删除当天日报，连带删除其下全部工作内容项与关联。不存在返回 404。

**响应**：`Result<Void>`

```json
{ "code": 200, "message": "成功", "data": null }
```

## 五、数据结构

### DailyReportMonthVO

| 字段 | 类型 | 说明 |
|---|---|---|
| month | string | 月份 YYYY-MM |
| reports | DailyReportVO[] | 有日报的天（按日期升序） |

### DailyReportVO

| 字段 | 类型 | 说明 |
|---|---|---|
| id | long | 日报ID |
| reportDate | string | 日期 YYYY-MM-DD |
| items | DailyReportItemVO[] | 工作内容列表 |
| createdAt | string | 创建时间(UTC) |
| updatedAt | string | 更新时间(UTC) |

### DailyReportItemVO

| 字段 | 类型 | 说明 |
|---|---|---|
| id | long | 工作内容项ID |
| content | string | 工作内容 |
| progress | int | 进度百分比 0-100 |
| todos | RelatedTodoVO[] | 关联的待办概要 |

### RelatedTodoVO

| 字段 | 类型 | 说明 |
|---|---|---|
| id | long | 待办ID |
| title | string | 标题 |
| status | string | 状态 0待处理/1已完成 |
| doneAt | string | 完成时间(UTC)，可空 |

## 六、前端对接建议

1. **月度表格渲染**：调用 4.1 拉取当月 reports，按 reportDate 映射到月历对应格子；空格子表示当天未填日报。
2. **编辑某天**：点开某天 -> 调 4.2 拉详情回填 -> 用户编辑后调 4.3 整体提交。
3. **关联待办**：编辑时点"关联待办" -> 调 `GET /api/todos/by-date/{date}` 拉当天待办（返回当天真实状态快照）供勾选，勾选的 id 放入 `items[].todoIds`。
4. **未来日期置灰**：前端可据今天日期置灰未来格子；即使绕过前端传未来日期，后端也会 4601 拒绝。
5. **status 字段**：待办 status 为字符串 `"0"`(待处理)/`"1"`(已完成)，与待办模块一致。
