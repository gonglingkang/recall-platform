# 需求管理接口文档（v1.2）

> 本文档供前端对接「需求管理」功能使用。所有接口需 JWT 登录，userId 由后端从令牌解析，前端无需传。

## 一、功能概述

需求是需求文档/会议纪要的归属载体，可 1:1 独占绑定一个月度绩效关键成果 K。绑定 K 后，需求的讨论中/进行中/开发完成三个状态由 K 状态映射驱动；未绑 K 时手动维护。进入不涉及时解绑 K；进入验收完成/发布完成时保留 K 关联（仅断开联动，便于事后追溯），之后 K 不再驱动。

需求必须归属一个主分类，可不选子分类（分类最多两级）。需求分类独立于待办分类，需单独维护。

**核心规则**：

| 规则 | 说明 |
|---|---|
| 状态 6 态 | 讨论中(0)/不涉及(1)/进行中(2)/开发完成(3)/验收完成(4)/发布完成(5) |
| 1:1 独占绑定 | 一个 K 只能被一个需求绑定；一个需求最多绑一个 K |
| 绑K跟K走 | 绑K时，讨论中/进行中/开发完成由 K 状态映射，禁止手动改这三态 |
| 未绑K手动 | 未绑K时，按手动状态机自由流转 |
| 进入脱钩态 | 进入不涉及解绑K；进入验收完成/发布完成保留K关联（仅断开联动） |
| 文档仅链接 | 文档只存标题+外部链接，不存文件本体 |
| 创建/编辑可绑K | 创建和编辑需求时传 keyResultId 即可绑定，无需单独接口 |
| 首次需求时间 | 区别于创建时间，用于补录历史需求或忘记维护时的准确首次时间，不能是未来日期；分页按此时间范围过滤 |
| 需求分类 | 独立于待办分类的两级分类（主分类+子分类），需求必选主分类、可选子分类 |

### K 状态映射（绑K时自动）

| K 状态 | 需求状态 |
|---|---|
| 未开始(0) | 讨论中(0) |
| 进行中(1) | 进行中(2) |
| 已完成(2) | 开发完成(3)，填 devCompleteDate |
| 已取消(3) | 解绑K，回讨论中(0) |
| K 被删除 | 解绑K，回讨论中(0) |

### 手动状态机（合法流转）

```
讨论中(0) ──> 不涉及(1) / 进行中(2)
不涉及(1) ──> 讨论中(0) / 进行中(2)
进行中(2) ──> 讨论中(0) / 不涉及(1) / 开发完成(3)
开发完成(3) ──> 进行中(2) / 不涉及(1) / 验收完成(4) / 发布完成(5)
验收完成(4) ──> 发布完成(5)（不可回退）
发布完成(5) ──> 终态，不可流转
```

> 绑K时额外约束：手动目标态不能是 {讨论中/进行中/开发完成}（这三态跟K走），只能改到 {不涉及/验收完成/发布完成}。进入不涉及解绑K；进入验收完成/发布完成保留K关联（仅断开联动）。
> 验收完成不可回退（不能回到开发完成/进行中/讨论中），只能继续到发布完成。

## 二、错误码

| 错误码 | 含义 | 触发场景 |
|---|---|---|
| 4701 | 需求标题已存在 | 创建/编辑时同用户下标题重复 |
| 4702 | 关键成果已被其他需求绑定 | 绑定的K已被另一个需求独占 |
| 4703 | 不能绑定已取消的关键成果 | 绑定的K状态为已取消 |
| 4704 | 当前状态不可绑定关键成果 | 需求处于不涉及/验收完成/发布完成时尝试绑K |
| 4710 | 需求分类名已存在 | 创建/编辑分类时同用户同父下名称重复 |
| 4711 | 需求分类下有子分类，无法删除 | 删除分类前需先删除子分类 |
| 4712 | 需求分类下有需求，无法删除 | 删除分类前需先迁移该分类下的需求 |
| 4713 | 子分类的父分类与传入主分类不一致 | 创建/编辑需求时子分类不属于传入的主分类 |
| 404 | 资源不存在 | 查询/操作不存在或不属于自己的需求/文档/K |
| 409 | 状态冲突 | 状态流转非法、终态不可变更、绑K后手动改K活跃态、已发布完成禁止编辑等 |
| 422 | 参数校验失败 | 标题为空、URL为空、首次需求时间为空或为未来日期、分页参数越界等 |

## 三、接口列表

### 需求接口

基础路径：`/api/requirements`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/requirements/page` | 需求分页列表（关键字/首次需求时间范围/状态过滤） |
| GET | `/api/requirements/{id}` | 需求详情（含文档+绑定的K摘要） |
| POST | `/api/requirements` | 创建需求（可选传 keyResultId 绑定K） |
| PUT | `/api/requirements/{id}` | 编辑需求（可改 title/description/firstDemandDate，keyResultId 传值绑定/传null解绑） |
| PATCH | `/api/requirements/{id}/status` | 状态变更（手动） |
| DELETE | `/api/requirements/{id}` | 删除需求（连带删文档） |

### 文档接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/requirements/{id}/documents` | 新增文档 |
| DELETE | `/api/requirement-documents/{docId}` | 删除文档 |

### 需求分类接口

基础路径：`/api/requirement-categories`（独立于待办分类 `/api/categories`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/requirement-categories` | 分类树（两级，主分类含子分类） |
| POST | `/api/requirement-categories` | 新增分类（parentId 空建主分类，非空建子分类） |
| PUT | `/api/requirement-categories/{id}` | 编辑分类（parentId 不可改，color 仅主分类可改） |
| DELETE | `/api/requirement-categories/{id}` | 删除分类（有子分类或下有需求均拒绝） |

### 4.3 创建需求

`POST /api/requirements`

**请求体**：`RequirementCreateReq`

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| title | String | 是 | 最长200字符 |
| description | String | 否 | 最长2000字符 |
| firstDemandDate | Date(YYYY-MM-DD) | 是 | 首次需求时间，不能是未来日期，可补录历史 |
| keyResultId | Long | 否 | 传则绑定K，绑定后状态跟K走 |
| categoryId | Long | 是 | 需求主分类ID（必选） |
| subCategoryId | Long | 否 | 需求子分类ID（可选，需属于传入主分类） |

```json
{
  "title": "登录功能改造",
  "description": "支持手机号登录",
  "firstDemandDate": "2026-07-01",
  "keyResultId": 10,
  "categoryId": 5,
  "subCategoryId": 8
}
```

**响应**：`Result<RequirementVO>`，初始 status 为 `"0"`（讨论中）。

**绑K规则**（传 keyResultId 时）：
- 仅需求处于 K 活跃态（创建时即讨论中，满足）允许绑定。
- K 必须属于当前用户，越权返回 404。
- K 状态不能是已取消，否则 4703。
- K 未被其他需求独占，否则 4702。
- 绑定后按 K 状态同步：K=未开始->讨论中；K=进行中->进行中；K=已完成->开发完成。

**分类规则**：
- categoryId 必填，必须是当前用户的主分类（parentId=null），否则 422。
- subCategoryId 可选；非空时必须是 categoryId 的子分类，否则 4713。

### 4.4 编辑需求

`PUT /api/requirements/{id}`

**请求体**：`RequirementUpdateReq`

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| title | String | 是 | 最长200字符，同用户唯一 |
| description | String | 否 | 最长2000字符 |
| firstDemandDate | Date(YYYY-MM-DD) | 是 | 首次需求时间，不能是未来日期，可补录历史 |
| keyResultId | Long | 否 | 全量覆盖：传值则绑该K（与当前不同先解绑再绑），传null则解绑（回讨论中） |
| categoryId | Long | 是 | 需求主分类ID（必选） |
| subCategoryId | Long | 否 | 需求子分类ID（可选，需属于传入主分类） |

```json
{
  "title": "登录功能改造",
  "description": "支持手机号+验证码登录",
  "firstDemandDate": "2026-07-01",
  "keyResultId": 10,
  "categoryId": 5,
  "subCategoryId": 8
}
```

**响应**：`Result<RequirementVO>`

**规则**：
- 发布完成（终态）的需求禁止编辑，返回 409。
- keyResultId 全量覆盖语义：传值则绑该 K（与当前不同先解绑再绑），传 null 则解绑（回讨论中，清 devCompleteDate）。
- 绑K约束同创建（4702/4703/4704）。
- 因 null 表示解绑，前端编辑时若需保持当前绑定不变，须带上当前绑定的 K id。

### 4.5 状态变更

`PATCH /api/requirements/{id}/status`

**请求体**：`RequirementStatusReq`

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| status | String | 是 | discussing/not_involved/in_progress/dev_done/acceptance_done/released |
| cancelReason | String | 否 | 仅切到 not_involved 时写入，最长500字符 |
| acceptanceDate | Date(YYYY-MM-DD) | 否 | 仅切到 acceptance_done 时写入，不传默认当天 |
| acceptancePerson | String | 否 | 仅切到 acceptance_done 时写入，验收人姓名，最长100字符 |
| releaseDate | Date(YYYY-MM-DD) | 否 | 仅切到 released 时写入，不传默认当天 |

```json
{
  "status": "acceptance_done",
  "acceptanceDate": "2026-07-15",
  "acceptancePerson": "张三"
}
```

**响应**：`Result<RequirementVO>`

**规则**：
- 必须符合手动状态机（见一、功能概述），非法流转返回 409。
- 绑K时禁止手动改 {讨论中/进行中/开发完成}（这三态跟K走），返回 409。
- 进入 {不涉及} 时自动解绑K；进入 {验收完成/发布完成} 时保留K关联（仅断开联动）。
- 发布完成为终态，不可再变更，返回 409。
- 验收完成不可回退，只能继续到发布完成，返回 409。
- 进入不涉及时填 cancelReason，清 devCompleteDate；进入验收完成填 acceptanceDate（不传默认当天）与 acceptancePerson，保留 devCompleteDate；进入发布完成填 releaseDate（不传默认当天），保留 devCompleteDate。
- 回退到讨论中/进行中时清 devCompleteDate。

### 4.6 删除需求

`DELETE /api/requirements/{id}`

**响应**：`Result<Void>`

> 连带删除该需求下的全部文档。已绑定的 K 不受影响（仅解除绑定关系）。

## 六、状态流转与K联动速查

**未绑K时（手动）**：按状态机流转，devCompleteDate 在进入开发完成时填当天，进入其他态时清空。

**绑K时（自动跟K）**：
- K->未开始：需求->讨论中，清devCompleteDate
- K->进行中：需求->进行中，清devCompleteDate
- K->已完成：需求->开发完成，填devCompleteDate
- K->已取消：解绑K，需求->讨论中，清devCompleteDate
- K被删除：解绑K，需求->讨论中，清devCompleteDate

**进入脱钩态（手动）**：
- 不涉及：解绑K，填cancelReason，清devCompleteDate
- 验收完成：保留K关联（仅断开联动），填acceptanceDate（不传默认当天）与acceptancePerson，保留devCompleteDate
- 发布完成：保留K关联（仅断开联动），填releaseDate（不传默认当天），保留devCompleteDate

> 注意：验收完成/发布完成是需求侧的独立状态，与 K 是否完成无关。绑K的需求要验收，须先等 K 完成使需求达到开发完成，再手动验收到验收完成。验收/发布后 K 状态变化不再驱动需求，但保留关联便于追溯。
> 验收完成不可回退，只能继续到发布完成。

### 7.2 新增分类

`POST /api/requirement-categories`

**请求体**：`RequirementCategoryCreateReq`

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| parentId | Long | 否 | 空=主分类，非空=子分类（最多两级） |
| name | String | 是 | 最长20字符，同用户同父下唯一 |
| color | String | 否 | 仅主分类可用，子分类强制为空 |
| sortOrder | Integer | 否 | 默认0 |

**规则**：
- 创建子分类时 parentId 必须是当前用户的主分类，且不能在子分类下再建（最多两级），否则 422。
- 同用户同父下名称唯一，冲突 4710。

### 7.3 编辑分类

`PUT /api/requirement-categories/{id}`

**请求体**：`RequirementCategoryUpdateReq`

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| name | String | 是 | 最长20字符，同用户同父下唯一 |
| color | String | 否 | 仅主分类可改，子分类设色 422 |
| sortOrder | Integer | 否 | - |

> parentId 不可变更。

### 7.4 删除分类

`DELETE /api/requirement-categories/{id}`

**响应**：`Result<Void>`

**规则**：
- 有子分类拒绝删除，4711（需先删子分类）。
- 分类下有需求拒绝删除，4712（需先迁移需求到其他分类）。
