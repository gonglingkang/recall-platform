## 0. 文档导读

本文档面向「实现人员」（含 AI 编码助手），目的是让待办系统从 0 到 1 落地。为降低理解成本，统一约定如下术语：

| 术语 | 含义 |
|------|------|
| 待办（Todo） | 系统核心对象，一条需要用户执行的事项，属于「日常执行层」 |
| 任务（Task） | 本文中等同于待办，不单独区分 |
| 大分类（Category） | 待办的第一层分类，如「公司事务」「生活事务」 |
| 子分类（Subcategory） | 待办的第二层分类，如「A 项目」「学习成长」 |
| 计划日期（Plan Date） | 待办计划完成的日期，默认为当天 |
| 完成日期（Done At） | 待办被标记完成的时间 |
| 月度规划（Monthly Plan） | 「规划层」对象，按月份管理本月的工作重心，包含「月度绩效工作」与「月团队冲刺」两类 |
| 月度绩效工作（Performance） | 用户本月个人需交付的关键成果（KR），按分类组织，带完成状态与完成时间 |
| 月团队冲刺（Team Sprint） | 团队级别的本月冲刺任务清单，用户用它了解「团队在干什么、哪些自己需要介入」 |
| 关键成果（KR） | 月度绩效工作下的具体交付项 |
| 派生（Derive） | 把规划层对象一键转成日常待办的过程，是规划↔执行闭环的关键动作 |

## 1. 项目背景与目标

### 1.1 背景

用户长期处于工作繁忙状态，日常需要处理大量来自公司、生活、学习等多方面的待办事项。但公司并未提供一套趁手的待办管理工具，现有笔记类工具又偏重记录、轻管理，导致：

- 事项散落在便签、聊天记录、大脑记忆中，容易遗漏；
- 无法快速区分「今天必须做」和「以后再做」；
- 缺乏完成情况的回顾，难以衡量自己的时间投入与产出。

### 1.2 目标

构建一套**个人专属、轻量高效、可分类、可回顾**的待办管理系统，帮助用户：

1. **集中收纳**：所有待办事项统一在一个入口管理，不再遗漏；
2. **聚焦当天**：默认聚焦今日待办，让每天的工作有明确焦点；
3. **分类清晰**：两层分类体系，让公司事务与生活事务井井有条；
4. **自动流转**：今日未完成事项次日自动延续，无需手动搬迁；
5. **持续提效**：通过回顾与统计，帮助用户持续优化时间分配。

### 1.3 成功指标（建议）

| 指标 | 目标 |
|------|------|
| 日活待办创建数 | 单用户每日平均创建 ≥ 3 条 |
| 今日完成率 | 周平均今日完成率 ≥ 70% |
| 次日自动延续触发率 | 体感上「不丢事项」 |
| 核心路径耗时 | 创建一条待办 ≤ 5 秒 |

## 2. 产品定位与核心价值

### 2.1 产品定位

一套**面向个人的私有化轻量待办系统**，强调「专注今日、清晰分类、自动流转、轻量回顾」。不追求企业级协作与多人派发，专注单用户的个人效率。

### 2.2 核心价值主张

- **Today First**：打开即看到今天该做什么；
- **Never Lost**：未完成的事项自动延到次日，绝不丢失；
- **Clear Bucket**：两层分类，公司 / 生活 / 学习各有归处；
- **Quick Capture**：极简创建，3 秒记下一条事项；
- **Plan & Execute**（v1.1 新增）：把月度绩效与团队冲刺统一管理，并可一键派生为日常待办，让「月度规划」与「每日执行」形成闭环，而不是两张割裂的表。

## 3. 用户角色与权限

### 3.1 角色定义

| 角色 | 说明 | 权限 |
|------|------|------|
| 普通用户 | 系统的唯一使用者（个人私有系统） | 注册、登录、管理自己的分类与待办、查看自己的统计 |
| 访客（未登录） | 未注册或未登录的访问者 | 仅可访问「首页（介绍页）」与「登录 / 注册页」 |

### 3.2 数据隔离原则（强制）

- **待办、分类、子分类数据严格按用户隔离**。用户 A 在任何情况下都无法查看、编辑、引用用户 B 的数据。
- 所有待办、分类相关接口在查询时必须强制带上 `当前登录用户 ID` 作为过滤条件，**禁止仅凭资源 ID 访问**。
- 统计、回顾数据也仅基于当前用户的数据生成。

## 4. 全局规则

> 本章规则贯穿全系统，所有模块共享，后续模块不再重复描述。

### 4.1 命名规范

- 待办标题：必填，最大长度 100 字符。
- 备注内容：选填，最大长度 2000 字符。
- 大分类名称：必填，最大长度 20 字符，同一用户下不可重名。
- 子分类名称：必填，最大长度 20 字符，同一大分类下不可重名。

### 4.2 待办状态机

待办有以下状态，状态流转必须遵循下方规则：

| 状态 | 英文标识 | 说明 |
|------|----------|------|
| 待处理 | `pending` | 已创建，尚未完成，等待执行 |
| 已完成 | `done` | 已被标记完成 |
| 已删除 | `deleted` | 软删除，进入回收站，可恢复 |

**状态流转规则：**

```
pending ──(标记完成)──> done
pending ──(删除)──────> deleted
done    ──(撤销完成)──> pending
done    ──(删除)──────> deleted
deleted ──(恢复)──────> 回到删除前的状态（pending 或 done）
deleted ──(彻底删除)──> 物理删除（不可恢复）
```

- 已完成可以撤销（回到 pending），删除均采用**软删除**，可在回收站恢复。

### 4.3 优先级

每个待办有一个优先级，用于排序与提示：

| 优先级 | 标识 | 视觉建议 |
|--------|------|----------|
| 高 | `high` | 红色标记 |
| 中 | `medium` | 橙色 / 默认 |
| 低 | `low` | 灰色 |

- 新建待办默认优先级为 `medium`。

### 4.4 日期与时区规则（关键）

- 系统所有「日期」概念统一按**用户本地时区**的「自然日」计算，而非 24 小时滚动。
- 「今天」= 用户当前本地日期 00:00:00 至 23:59:59。
- **计划日期**字段只精确到「天」（存储为日期，不带时分秒，或存储当天 00:00），用于「今日待办」「未完成自动延续」等判断。
- 所有时间戳（如完成时间 `doneAt`、创建时间 `createdAt`）使用 UTC 存储，展示时转为本地时区。

### 4.5 次日自动延续规则（核心业务，务必实现）

> 这是用户最看重的需求之一：「今天没完成，明天要能看到」。

**规则定义：**

- 当一个待办满足：`状态 = pending` **且** `计划日期 < 今天`，称为**逾期未完成待办**。
- 系统在用户每次打开「今日」视图时（或在每日凌晨的定时任务中），将这些逾期未完成的待办的**计划日期更新为「今天」**。
- 更新计划日期后，该待办自然出现在「今日待办」列表中。

**实现建议（后端两选一）：**

1. **懒加载方式（推荐 MVP 用）**：用户请求「今日待办」接口时，后端先把 `pending` 且 `计划日期 < 今天` 的待办的 `计划日期` 更新为今天，再返回今日列表。优点：实现简单、即时生效。
2. **定时任务方式**：每天凌晨 00:05（用户本地时区）跑一次定时任务，批量把逾期未完成待办的计划日期更新为当天。优点：数据一致性更好，列表查询更快。

- 建议两种结合：定时任务做兜底，懒加载做即时修正。
- **注意**：已完成（`done`）和已删除（`deleted`）的待办**不参与**自动延续。
- 自动延续应记录一个 `延续次数` 或在备注里标注，方便用户回顾，但 MVP 可不做。

### 4.6 排序规则

「今日待办」列表默认排序权重（从上到下）：

1. 优先级：high > medium > low；
2. 同优先级内：未完成（pending）在前，已完成（done）在后；
3. 同状态同优先级内：按创建时间升序（先创建的在前）；
4. 可选：置顶（pin）的待办始终在最前（见 6.6 节）。

### 4.7 软删除与回收站

- 删除待办、分类均为软删除（标记 `deletedAt`）。
- 待办删除后进入「回收站」，保留 30 天，30 天后由定时任务物理删除。
- 回收站内可「恢复」待办。恢复时：
  - 若其所属分类 / 子分类已被删除，则恢复到默认分类（或提示用户重新选择分类）。
- 删除大分类时：见 6.7 节的分类删除规则。

## 6. 功能详细需求

### 6.1 首页（介绍页 / 落地页）

**功能说明：**

面向**未登录访客**的系统介绍页，承担「产品介绍」与「引导注册登录」两个职责。已登录用户访问根路径时直接跳转「今日待办」，不展示本页。

**页面内容：**

1. **顶部导航栏**：左侧系统名称 / Logo，右侧「登录」「注册」按钮。
2. **主视觉区（Hero）**：
   - 一句主标题（如「专注今日，事事有归处」）；
   - 一句副标题，说明系统价值；
   - 一个主 CTA 按钮「立即开始」→ 跳转注册；
   - 一个次 CTA「已有账号？登录」→ 跳转登录。
3. **核心卖点区**：3～4 个特性卡片，每个卡片一个图标 + 标题 + 一句话描述。建议卖点：
   - 「今日聚焦」：打开即看到今天该做什么；
   - 「永不丢失」：未完成事项次日自动延续；
   - 「两层分类」：公司 / 生活 / 学习井井有条；
   - 「极简记录」：3 秒记下一条事项。
4. **使用步骤区**：3 步引导（注册登录 → 建分类 → 记待办），让用户快速理解。
5. **页脚**：版权信息、版本号。

**业务规则：**

- 本页**不需要登录**即可访问。
- 已登录用户访问 `/`（首页路由）时，**自动重定向**到 `/today`（今日待办）。

**前端实现要点：**

- 路由：`/`
- 未登录访问 `/today` 等需鉴权页面时，重定向到 `/login`，并在 query 中带 `redirect=/today`，登录成功后跳回。

### 6.2 账户模块

#### 6.2.1 注册

**功能说明：**

新用户通过账号密码注册。

**字段：**

| 字段 | 必填 | 校验规则 |
|------|------|----------|
| 账号（用户名） | 是 | 4～20 位，字母 / 数字 / 下划线，不可与已有用户重复 |
| 邮箱 | 是（建议） | 合法邮箱格式，不可重复；用于找回密码 |
| 密码 | 是 | 8～32 位，至少包含字母和数字 |
| 确认密码 | 是 | 必须与密码一致 |

**业务规则：**

- 用户名全局唯一，邮箱全局唯一，重复时给出明确错误提示。
- 密码必须**加密存储**（如 bcrypt），严禁明文。
- 注册成功后：自动登录并跳转「今日待办」。
- 注册时为用户自动创建一组**默认大分类**（见 6.4.1），降低首次使用门槛。

**前端实现要点：**

- 路由：`/register`
- 表单实时校验；提交时按钮 loading，防重复提交。
- 错误提示就近展示在对应字段下方。

#### 6.2.2 登录

**功能说明：**

已注册用户通过账号（或邮箱）+ 密码登录。

**字段：**

| 字段 | 必填 | 校验规则 |
|------|------|----------|
| 账号或邮箱 | 是 | — |
| 密码 | 是 | — |

**业务规则：**

- 登录成功后签发令牌（建议 JWT 或 Session）。
- 登录态有效期建议 7 天（可配置），支持「记住我」延长至 30 天。
- 若带 `redirect` 参数，登录成功后跳回该参数所指页面；否则跳转 `/today`。
- 登录失败时提示「账号或密码错误」，**不区分**是账号不存在还是密码错误（安全考虑）。
- 连续 5 次失败后，该账号 5 分钟内禁止登录（防爆破，P1）。

**前端实现要点：**

- 路由：`/login`
- 令牌存储建议：httpOnly Cookie（更安全）或 localStorage。
- 全局 axios 拦截器：401 时清除登录态并跳转登录页。

#### 6.2.3 退出登录

- 用户主动退出，清除前端登录态，跳转首页或登录页。
- 后端可选地将当前令牌加入黑名单（P1）。

### 6.3 待办核心模块

#### 6.3.1 今日待办（核心默认页）

**功能说明：**

已登录用户的主工作台，展示「今天需要处理」的所有待办。这是用户每天最常打开的页面。

**页面内容：**

1. **页面头部**：
   - 标题「今日待办」+ 当前日期（如 2026-06-28 周日）；
   - 今日统计条：`今日共 X 项 / 已完成 Y 项 / 完成率 Z%`，配一个进度条。
2. **快速创建栏**：一个输入框 +（可选）优先级 / 分类选择，回车或点按钮快速创建（见 6.3.2）。
3. **待办列表**：按 4.6 排序规则展示今日待办。
   - 每条待办项展示：完成勾选框、标题、优先级标记、所属分类（大分类 > 子分类）、（可选）提醒时间、操作按钮（编辑 / 删除 / 置顶）。
   - 已完成的待办以删除线 + 置灰展示，默认折叠到列表底部或单独分组。
4. **空状态**：今日没有待办时，展示友好的空状态插画与文案（如「今天清空了，去享受生活吧 🎉」），并引导创建。

**业务规则：**

- 「今日待办」= 当前用户下，`状态 ≠ deleted` **且** `计划日期 = 今天` 的所有待办。
- 进入页面时触发 4.5 的**次日自动延续**逻辑（逾期 pending 的待办计划日期更新为今天）。
- 列表数据来自当前用户，**禁止跨用户**。

**前端实现要点：**

- 路由：`/today`
- 创建、完成、删除操作建议**乐观更新**（先改 UI 再等接口），失败再回滚，保证流畅。
- 完成勾选建议带一个轻微的动画反馈。

#### 6.3.2 待办创建

**功能说明：**

支持两种创建方式：① 列表上方的「快速创建」；② 点击「新建」按钮打开完整表单。

**字段：**

| 字段 | 必填 | 说明 |
|------|------|------|
| 标题 | 是 | 最长 100 字符 |
| 大分类 | 是 | 下拉选择，默认选中「上次使用的分类」或「公司事务」 |
| 子分类 | 否 | 依赖大分类联动，下拉选择；允许为「无」 |
| 计划日期 | 是 | 默认今天；可改为今天 / 明天 / 指定日期 |
| 优先级 | 否 | 默认 medium |
| 备注 | 否 | 最长 2000 字符 |
| 提醒时间 | 否（P1） | 到点推送 / 高亮提醒 |

**业务规则：**

- 计划日期默认今天。
- 快速创建：仅需标题，其余字段取默认值，**回车即提交**。
- 创建成功后，若当前在「今日」视图且计划日期为今天，则新待办出现在列表中并高亮一下。

**前端实现要点：**

- 快速创建输入框始终聚焦友好，支持 `Enter` 提交、`Esc` 清空。
- 大分类切换时，子分类下拉要联动刷新。

#### 6.3.3 待办编辑

- 点击待办的编辑按钮，弹出编辑面板 / 抽屉 / 弹窗。
- 所有字段均可编辑。
- 编辑保存后列表实时更新。
- 校验规则同创建。

#### 6.3.4 待办完成 / 撤销完成

- 点击勾选框：pending → done，记录 `doneAt = 当前时间`。
- 再次点击：done → pending，清空 `doneAt`。
- 已完成的待办在列表中样式变化（删除线、置灰、移到底部）。
- 完成时建议有动效与（可选）轻量正向反馈。

#### 6.3.5 待办删除 / 恢复

- 删除为软删除（进入回收站）。
- 删除前建议二次确认（或支持撤销 toast）。
- 回收站（P1）内可恢复，恢复规则见 4.7。

#### 6.3.6 待办详情

- 点击待办标题或卡片，打开详情抽屉 / 页面。
- 展示完整字段：标题、备注、分类、优先级、计划日期、创建时间、完成时间、状态。
- 详情内可直接编辑、完成、删除。

#### 6.4.1 大分类（Category）

**功能说明：**

用户自定义的顶层分类，如「公司事务」「生活事务」「学习成长」。

**字段：**

**业务规则：**

- 大分类被删除时，其下子分类按 6.4.1 的删除策略处理（一起删或迁移）。
- 待办的子分类允许为空（只选大分类）。

**前端实现要点：**

- 分类管理页：左侧大分类列表，右侧选中大分类的子分类列表（典型的主从布局）。
- 大分类与子分类都支持拖拽排序。

### 6.8 月度规划模块（规划层，v1.1 新增）

> 这是基于用户实际工作场景（公司每月有月绩效、有团队冲刺）新增的「规划层」模块。它和「日常待办」是**两个层级**：
> - **规划层（月度）**：本月要交付什么关键成果、团队在冲什么——颗粒度大，按月组织。
> - **执行层（日常）**：今天/本周怎么一步步推进——颗粒度小，按天组织。
>
> 本模块的核心使命：**让月度规划与每日执行不再割裂**。规划能一键派生为待办，待办的完成又能回流反哺月度进度。

---

#### 6.8.1 月度绩效工作（个人 KR 管理）

**功能说明：**

用户维护**自己本月**的关键成果（KR），按「分类」组织，每条 KR 记录完成状态与完成时间。对应截图 1 的结构：`分类 / 关键成果 / 完成状态 / 完成时间`。

**页面内容：**

1. **月份切换器**：顶部可切换月份（默认当月），如「2026 年 6 月」左右箭头切换。
2. **月度概览条**：`本月 KR 共 X 项 / 已完成 Y 项 / 完成率 Z%`，配进度条。
3. **KR 列表（按分类分组）**：以「分类」为分组维度，每个分类下若干「关键成果」行。每行展示：
   - 关键成果标题；
   - 完成状态（待完成 / 已完成，建议用勾选或标签）；
   - 完成时间（日期选择，格式 月-日）；
   - 操作：编辑 / 删除 / **派生为待办**。
4. **分类管理**：绩效分类可增删改（如「天宫建模开发 / 数据中心建模开发 / 建模支持」）。这些是**绩效模块自己的分类**，与日常待办的两层分类相互独立，避免混淆。
5. **空状态**：本月尚无 KR 时，引导「新建分类 → 添加关键成果」。

**字段：**

| 字段 | 必填 | 说明 |
|------|------|------|
| 月份 | 是 | 形如 `2026-06`，每条 KR 归属一个月份 |
| 分类 | 是 | 绩效分类，最长 20 字符，同月同用户下唯一 |
| 关键成果标题 | 是 | 最长 100 字符 |
| 完成状态 | 是 | `pending` / `done`，默认 `pending` |
| 完成时间 | 否 | 完成时填写，精确到天（月-日） |
| 备注 | 否 | 该 KR 的说明 / 验收标准 |
| 来源派生标记 | 否 | 若由团队冲刺派生而来，记录来源 ID（见 6.8.3） |

**业务规则：**

- 绩效数据**严格按用户 + 月份**隔离，不同用户、不同月份互不可见。
- 月份切换时只加载该月数据。
- **跨月不自动延续**：绩效 KR 不像日常待办那样自动滚到下月。若本月未完成，需用户手动处理：
  - 方式 A：手动修改其月份到下月（「结转到下月」按钮）；
  - 方式 B：保持在本月记录历史，下月新建。
  - MVP 建议提供「结转到下月」一键操作，避免重复录入。
- **完成状态回流（P2，可选增强）**：当一条 KR 的所有派生待办都完成时，可在 KR 上提示「相关待办已全部完成，是否标记本 KR 已完成？」由用户确认，不自动改。
- 已完成 / 未完成都保留用于月末回顾，**不软删除进回收站**，删除即从列表移除（或保留历史，建议可配）。

**前端实现要点：**

- 路由：`/plan/performance/:month?`（如 `/plan/performance/2026-06`），不带 month 默认当月。
- 列表采用「分类分组 + 组内 KR 行」结构，分类标题行可折叠。
- 支持行内编辑（点击标题直接改）与批量录入（连续添加多条 KR）。
- 派生待办按钮见 6.8.3。

#### 6.8.2 月团队冲刺（团队任务清单）

**功能说明：**

用户维护**团队本月**的冲刺任务清单，用来掌握「团队在干什么、哪些工作需要自己介入」。对应截图 2 的结构：`月份 + 任务清单`，是团队级别的大颗粒任务。

**页面内容：**

1. **月份切换器**：同绩效，默认当月。
2. **冲刺任务列表**：每条冲刺任务展示：
   - 任务标题（如「低代码服务能力建设」「数据中心迭代」「天官验证环境搭建」）；
   - 状态（进行中 / 已完成 / 阻塞）；
   - **是否需我介入**标记（核心字段，见下方，这是用户最关心的「团队还涉及什么工作需要介入」）；
   - 负责人 / 相关模块（可选）；
   - 操作：编辑 / 删除 / **派生为待办**。
3. **介入视图筛选**：顶部提供「仅看需我介入」快捷筛选，一眼定位自己要跟进的冲刺项。
4. **空状态**：引导录入团队冲刺任务。

**字段：**

| 字段 | 必填 | 说明 |
|------|------|------|
| 月份 | 是 | 形如 `2026-06` |
| 任务标题 | 是 | 最长 100 字符 |
| 状态 | 是 | `in_progress` / `done` / `blocked` |
| needInvolved | 是 | 是否需我介入，布尔，默认 `false` |
| owner | 否 | 负责人姓名（纯文本，团队系统不强关联） |
| module | 否 | 相关模块 / 系统（如「数据中心」「天宫」） |
| 备注 | 否 | 说明、风险、依赖 |

**业务规则：**

- 团队冲刺同样按用户 + 月份隔离（这是「我的团队冲刺笔记」，不是多人协作系统）。
- `needInvolved = true` 的项在「月度总览」和「需我介入」筛选中高亮提示。
- 状态流转：`in_progress` ⇄ `done`，`blocked` 为异常态，需在备注说明阻塞原因。
- 跨月处理同绩效：提供「结转到下月」。

**前端实现要点：**

- 路由：`/plan/sprint/:month?`
- `needInvolved` 用显眼的开关 / 角标，便于一眼识别。
- 「仅看需我介入」是高频筛选，建议做成顶部 Tab 或快捷过滤器。

#### 6.8.3 规划 → 待办的派生（闭环关键动作）

**功能说明：**

无论绩效 KR 还是团队冲刺任务，都支持**一键派生为日常待办**，让规划落到每天执行。

**派生规则：**

- 在绩效 KR 或冲刺任务上点「派生为待办」→ 弹出一个预填表单：
  - 标题：默认带入 KR / 冲刺任务标题（可改）；
  - 计划日期：默认今天（可改为某天）；
  - 大分类 / 子分类：默认带「公司事务」（或上次使用）；
  - 优先级：默认 medium；
  - 备注：默认带入「来源：[月度绩效-天宫建模开发] XXX」字样，便于追溯。
- 确认后创建一条日常待办，并在原 KR / 冲刺任务上记录「已派生 N 条待办」（`derivedTodoIds`）。
- **一条规划项可派生多条待办**（一个 KR 可能拆成多天多个待办推进）。

**关联与回流：**

- 派生关系是**单向记录**（规划 → 待办 ID 列表），不强制双向同步。
- 在 KR / 冲刺详情里可看到「关联待办」列表及其完成情况（P2）。
- 删除被派生的待办时，不影响原规划项；删除规划项时，仅解除关联，不删除已派生的待办。

**前端实现要点：**

- 派生按钮在每行操作区；派生后给一个 toast「已创建待办，可在今日待办查看」并提供跳转链接。

#### 6.8.4 月度总览（一页看本月）

**功能说明：**

一个月度规划入口页，把本月绩效、团队冲刺、相关待办聚合展示，方便月初规划、月末复盘。

**页面内容：**

1. 月份切换 + 月度总进度（绩效完成率 + 冲刺完成率）。
2. 左侧：本月绩效 KR 概览（按分类，带完成数）。
3. 右侧：本月团队冲刺（高亮「需我介入」项）。
4. 底部：本月已派生的待办完成情况汇总。

**前端实现要点：**

- 路由：`/plan/:month?`，作为「月度规划」的总入口，绩效与冲刺是其子页 / 子 Tab。

**布局建议：**

- 左侧导航在「今日」下方新增「月度规划」分组，展开：月度总览 / 绩效工作 / 团队冲刺。

#### 6.9.2 修改密码

- 需输入旧密码 + 新密码 + 确认新密码。
- 新密码规则同注册。

#### 6.9.3 偏好设置

- 默认优先级、默认大分类。
- 「每日开始时间」（影响「今天」的计算，默认 00:00，部分用户希望按 04:00 翻日）。
- 提醒通知总开关（P1）。
- 主题：浅色 / 深色 / 跟随系统（P2）。

## 7. 全局业务流程

### 7.1 新用户首次使用流程

```
访问首页 → 点「立即开始」→ 注册 → 自动登录
   → 自动生成默认分类（公司/生活/学习）
   → 进入今日待办（空状态，引导创建第一条）
   → 创建第一条待办 → 出现在今日列表
```

### 7.2 日常使用主流程

```
打开系统（已登录）
   → 若是首次进入「今天」，先执行次日自动延续（逾期 pending → 计划日期改今天）
   → 展示今日待办 + 今日概览
   → 用户逐条勾选完成 / 编辑 / 删除
   → 剩余未完成的，次日自动延续
```

### 7.3 待办生命周期

```
创建（pending，计划日期=今天）
   → 当天完成 → done（记录 doneAt）
   → 当天未完成 → 次日自动延续（计划日期=明天，即新的今天）
   → 任意时刻删除 → 进入回收站 → 可恢复或 30 天后清除
```

### 7.4 月度规划与日常执行的闭环（v1.1 新增）

```
月初：进入「月度规划」
   → 维护本月绩效工作（按分类录入 KR）
   → 维护本月团队冲刺（标记「需我介入」项）
   ↓
日常：把规划派生为待办
   → KR / 冲刺项 → 一键「派生为待办」→ 进入今日待办执行
   → 关联关系记录在规划项上（derivedTodoIds）
   ↓
执行：在今日待办中逐条完成
   ↓
月末：进入「月度总览」复盘
   → 看绩效完成率 / 冲刺完成率 / 派生待办完成情况
   → 未完成的 KR / 冲刺 → 「结转到下月」继续推进
```

## 8. 非功能需求

### 8.1 性能

- 今日待办列表首屏加载 ≤ 1 秒（100 条以内）。
- 创建 / 完成 / 删除等操作响应 ≤ 300ms（前端乐观更新，体感即时）。
- 列表分页或虚拟滚动，单页加载上限 100 条。

### 8.2 安全

- 密码加密存储（bcrypt 等单向哈希），禁明文。
- 所有接口强制鉴权，待办 / 分类接口强制按 `当前用户 ID` 过滤。
- 防 SQL 注入（参数化查询）、防 XSS（输出转义）。
- 登录失败次数限制（见 6.2.2）。
- 敏感操作（删除分类等）二次确认。

### 8.3 兼容性

- 浏览器：Chrome、Edge、Safari、Firefox 近 2 个大版本。
- 响应式：桌面端为主，需兼容移动端浏览器（竖屏可用）。
- 移动端原生 App 可作为后续迭代。

### 8.4 可用性 / 健壮性

- 软删除 + 回收站，防误删。
- 接口失败时前端有明确错误提示，且支持重试。
- 网络断开时，前端尽量缓存待办列表，恢复后同步。
