# 个人月度绩效接口文档（v2.0 · 目标O+关键成果K）

> 本文档供前端对接使用。后端已按此契约实现。
> 设计核心：**目标 O 的进度、状态、完成时间均由其下关键成果 K 实时派生计算**，O 表不存这些字段，查询时聚合算出。

## 通用约定

- 接口前缀：`/api`
- 鉴权：所有接口需登录，请求头带 `Authorization: Bearer <token>`
- 统一响应：`{ "code": 200, "message": "成功", "data": ... }`，`code===200` 为成功
- 月份格式：`YYYY-MM`（如 `2026-07`），后端正则校验
- 数据隔离：所有查询/操作按当前登录用户隔离
- 字段命名：后端驼峰（如 `planCompleteDate`），JSON 序列化即驼峰

## 状态码与状态机

### 关键成果 K 状态码

数据库与 API 均使用**数字码**（字符串形式），前端自行映射文案：

| 数字码 | 含义 | 建议文案 |
|---|---|---|
| `"0"` | 未开始 | 未开始 |
| `"1"` | 进行中 | 进行中 |
| `"2"` | 已完成 | 已完成 |

### K 状态机（严格线性 + 跳级完成）

仅以下流转合法，其余流转后端返回 `409 状态流转非法`：

```
未开始(0) ──开始──> 进行中(1)
未开始(0) ──完成──> 已完成(2)   [跳级完成：事情已做完]
进行中(1) ──完成──> 已完成(2)
已完成(2) ──取消完成──> 进行中(1)
```

非法流转示例（被拒绝）：进行中→未开始、已完成→未开始、同状态切换。

### O 的派生状态

目标 O 的 status 由其下 K 聚合派生，同样使用数字码：
- 全部 K 未开始(0) → O 未开始(0)
- 任一 K 进行中(1) 或部分已完成(2) → O 进行中(1)
- 全部 K 已完成(2) → O 已完成(2)

## 一、目标 O

### 1. 查询某月目标列表（含其下所有 K，树形）

`GET /api/objectives?month=2026-07`

**说明**：返回该月所有目标，每个目标内嵌其下所有关键成果。O 的 `progress`/`status`/`planCompleteDate`/`actualCompleteDate` 是**派生字段**，已聚合算好返回。

**响应**：
```json
{
  "code": 200,
  "data": [
    {
      "id": 1,
      "month": "2026-07",
      "name": "提升产品体验",
      "description": "本季度核心目标",
      "progress": 50,
      "status": "1",
      "planCompleteDate": "2026-07-31",
      "actualCompleteDate": null,
      "keyResults": [
        {
          "id": 11,
          "name": "完成首页改版",
          "description": "重构首页布局与交互",
          "status": "2",
          "planCompleteDate": "2026-07-15",
          "completeDate": "2026-07-12"
        },
        {
          "id": 12,
          "name": "性能优化",
          "description": "首屏加载降至1秒内",
          "status": "0",
          "planCompleteDate": "2026-07-31",
          "completeDate": null
        }
      ]
    }
  ]
}
```

### 2. 新增目标 O

`POST /api/objectives`

**请求体**：
```json
{
  "month": "2026-07",
  "name": "提升产品体验",
  "description": "本季度核心目标"
}
```

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| month | string | 是 | 格式 YYYY-MM |
| name | string | 是 | 最长100字符 |
| description | string | 否 | 最长2000字符 |

**响应**：返回创建后的 O（派生字段此时无 K，progress=0、status=`"0"`、完成时间为 null）。
```json
{
  "code": 200,
  "data": {
    "id": 1,
    "month": "2026-07",
    "name": "提升产品体验",
    "description": "本季度核心目标",
    "progress": 0,
    "status": "0",
    "planCompleteDate": null,
    "actualCompleteDate": null,
    "keyResults": []
  }
}
```

### 3. 编辑目标 O

`PUT /api/objectives/{id}`

**请求体**（字段均可空，按需更新）：
```json
{
  "name": "提升产品体验(修订)",
  "description": "更新后的描述"
}
```

**响应**：返回更新后的 O（含派生字段 + 其下 K 列表）。

### 4. 删除目标 O

`DELETE /api/objectives/{id}`

**说明**：**连带删除其下所有关键成果 K**。

**响应**：
```json
{ "code": 200, "message": "成功", "data": null }
```

## 二、关键成果 K

### 5. 新增关键成果 K

`POST /api/key-results`

> `objectiveId` 放请求体指定归属目标 O。K 的全部接口统一在 `/api/key-results` 下。

**请求体**：
```json
{
  "objectiveId": 1,
  "name": "完成首页改版",
  "description": "重构首页布局与交互",
  "status": "0",
  "planCompleteDate": "2026-07-15"
}
```

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| objectiveId | long | 是 | 归属目标ID，目标不存在或不属于当前用户返回 404 |
| name | string | 是 | 最长100字符 |
| description | string | 否 | 最长2000字符 |
| status | string | 否 | `"0"`未开始/`"1"`进行中/`"2"`已完成，默认 `"0"` |
| planCompleteDate | string(date) | 否 | 计划完成时间，格式 YYYY-MM-DD |

> **注意**：`completeDate`（实际完成时间）由后端管理，请求体**不接受**该字段。切换为已完成(2) 时后端自动填当天，切回非已完成时清空。

**响应**：返回创建后的 K。
```json
{
  "code": 200,
  "data": {
    "id": 11,
    "name": "完成首页改版",
    "description": "重构首页布局与交互",
    "status": "0",
    "planCompleteDate": "2026-07-15",
    "completeDate": null
  }
}
```

### 6. 编辑关键成果 K

`PUT /api/key-results/{id}`

**请求体**（字段均可空，按需更新）：
```json
{
  "name": "完成首页改版(修订)",
  "description": "更新描述",
  "planCompleteDate": "2026-07-20"
}
```

> 编辑**不改变** status 和 completeDate。要改进度/状态请用状态切换接口（接口7）。

**响应**：返回更新后的 K。

### 7. 切换关键成果 K 的状态（改变进度的唯一入口）

`PATCH /api/key-results/{id}/status`

**请求体**：
```json
{
  "status": "2"
}
```

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| status | string | 是 | `"0"`未开始/`"1"`进行中/`"2"`已完成；须为合法流转（见状态机），否则 409 |

**后端自动维护 completeDate**：
- status → 已完成(2)：completeDate 自动设为当天（若已有值则保留，不覆盖）
- status → 进行中(1)（取消完成）：completeDate 清空

**响应**：返回更新后的 K（completeDate 已按规则更新）。
```json
{
  "code": 200,
  "data": {
    "id": 11,
    "name": "完成首页改版",
    "description": "重构首页布局与交互",
    "status": "2",
    "planCompleteDate": "2026-07-15",
    "completeDate": "2026-07-01"
  }
}
```

### 8. 删除关键成果 K

`DELETE /api/key-results/{id}`

**说明**：删除 K 后，其归属的 O 的派生进度会自动重算（下次查询 O 时反映）。

**响应**：
```json
{ "code": 200, "message": "成功", "data": null }
```

## 三、O 的派生计算规则（前端无需调用，了解即可）

查询目标 O 时，后端按其下所有 K 实时聚合：

| O 的派生字段 | 计算规则 |
|---|---|
| `progress` | `已完成K数 / K总数 × 100`，取整；无 K 时为 0 |
| `status` | 全部 K 未开始(0) → `0`；任一进行中(1) 或部分已完成(2) → `1`；全部已完成(2) → `2` |
| `planCompleteDate` | `max(K.planCompleteDate)`；无 K 时为 null |
| `actualCompleteDate` | 仅当所有 K 都已完成(2) 时 = `max(K.completeDate)`；否则 null |

**举例**：O 下有 4 个 K，2 个已完成(2)、1 个进行中(1)、1 个未开始(0) → `progress=50`、`status="1"`、`actualCompleteDate=null`。

## 四、数据结构定义

### ObjectiveVO（目标）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | long | 目标ID |
| month | string | 月份 YYYY-MM |
| name | string | 目标名称 |
| description | string | 目标描述 |
| progress | int | 进度 0-100（派生） |
| status | string | 状态 `"0"`未开始/`"1"`进行中/`"2"`已完成（派生） |
| planCompleteDate | string(date) | 计划完成时间（派生，max of K） |
| actualCompleteDate | string(date) | 实际完成时间（派生，全K完成时max of K） |
| keyResults | KeyResultVO[] | 关键成果列表 |

### KeyResultVO（关键成果）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | long | 关键成果ID |
| name | string | 名称 |
| description | string | 描述 |
| status | string | 状态 `"0"`未开始/`"1"`进行中/`"2"`已完成 |
| planCompleteDate | string(date) | 计划完成时间 |
| completeDate | string(date) | 实际完成时间（后端管理） |

## 五、错误码

| code | 含义 | 触发场景 |
|---|---|---|
| 200 | 成功 | |
| 400 | 请求参数错误 | 路径参数缺失等 |
| 401 | 未登录 | 未带 token 或 token 失效 |
| 404 | 资源不存在 | O/K 不存在或不属于当前用户 |
| 409 | 状态流转非法 | K 状态切换不符合状态机（如进行中→未开始） |
| 422 | 参数校验失败 | month 格式错、name 为空、status 非法值 |
| 503 | 服务不可用 | 占位 |

## 六、联调说明

1. **K 的 completeDate 前端不要传**：新增/编辑 K 的请求体里不要带 `completeDate`，它由状态切换接口自动维护。前端展示时直接读返回值即可。
2. **O 的派生字段前端不要传**：新增/编辑 O 时传 `progress`/`status`/`planCompleteDate`/`actualCompleteDate` 无效（后端忽略）。
3. **改 K 进度的唯一方式**是调 `PATCH /api/key-results/{id}/status`，不要用编辑接口改 status。状态切换须符合状态机，非法流转返回 409。
4. **删除 O 会连带删 K**，前端删 O 前应有二次确认。
5. **前端展示 O 的进度条**：用 `progress` 字段（0-100）；**状态标签**用 `status` 字段。
6. 月份切换：列表接口传 `month` 参数，格式 `YYYY-MM`。
7. Swagger UI：`http://localhost:20020/swagger-ui.html`，分组"月度绩效目标"。
